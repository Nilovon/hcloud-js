## Conventions

### Endpoint methods return the API envelope

Methods that map to an endpoint return exactly what the API returns, with
snake_case fields as in the
[Hetzner documentation](https://docs.hetzner.cloud/reference/cloud):

```typescript
const { servers, meta } = await client.servers.list();
const { server } = await client.servers.get(42);
const { server: created, action, next_actions, root_password } = await client.servers.create({ ... });
const { action: reboot } = await client.servers.reboot(42);
await client.sshKeys.delete(7); // endpoints answering 204 resolve to undefined
```

### Helpers return plain items

Every listable resource additionally has:

| Method                  | Returns                                            |
| ----------------------- | -------------------------------------------------- |
| `listAll(params?)`      | `Item[]` - all pages                               |
| `iterate(params?)`      | `AsyncGenerator<Item>` - lazily, page by page      |
| `iteratePages(params?)` | `AsyncGenerator<ListResponse>`                     |
| `first(params?)`        | `Item \| undefined`                                |
| `getByName(name)`       | `Item \| undefined` (resources with a name filter) |

See [Pagination](/docs/pagination).

### Actions

Resources with actions have

- one method per action (`client.servers.powerOn(id)`, `client.volumes.resize(id, params)`, ...),
- `listActions(id, params?)` and `getAction(id, actionId)` for the actions of one resource,
- an `actions` sub-client (`client.servers.actions.list()`, `.get()`, `.listAll()`,
  `.waitFor()`) for the actions of the resource type.

See [Waiting for Actions](/docs/actions).

### Request options

The last argument of every method is an optional
[`RequestOptions`](/docs/configuration#request-options) object with `signal`,
`timeout`, `retry` and `headers`.

### Types and schemas

For every endpoint the package exports the parameter and response types
(`CreateServerParams`, `CreateServerResponse`), the entity types (`Server`) and
the Zod schemas behind them (`serverSchema`, `createServerRequestSchema`).
See [Utilities](/docs/utils#zod-schemas).
